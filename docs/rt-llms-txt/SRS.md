## 1. Purpose and background

rt-ed.co.il has 25 programs, 123 courses, 349 articles and 3 lecturer profiles. The old `llms.txt` was a stale snapshot: 42% of courses and 99% of articles were missing, and several links were dead or redirected.

A static file goes stale whenever content is published. The files built on 2026-11-02 (`llms/llms.txt`, `llms/llms-full.txt`) were generated by a script from the sitemaps. This plugin replaces that manual step: the files are generated from WordPress content and rebuilt when content changes.

Goals:
1. `llms.txt` (curated) and `llms-full.txt` (complete) always reflect published content.
2. Editorial control stays with the SEO team: intro text, key facts, grouping and which articles are featured.
3. No measurable load added to the site (see the RT Source Tracker history, where a plugin slowed the server).

## 2. Scope

In scope: generating and serving the two files, an admin settings page, per-post controls, caching and invalidation, conflict detection, a bulk tool to assign domains to existing content.

Out of scope for v1:
- Bot traffic analytics (the RT Source Tracker plugin covers attribution).
- Link checking or SEO scoring.
- Multilingual output (the site is Hebrew only).
- Multisite.
- Editing `robots.txt` or the sitemap.

## 3. Users

| Role | Needs |
|---|---|
| SEO / marketing editor | Edit the intro and facts, feature articles, preview and regenerate, no code |
| Content editor | Publish content and tick two optional boxes at most; nothing else changes |
| Developer / admin | Install, deploy, configure the server, roll back |
| AI crawlers and agents | Fetch both files as UTF-8 plain text, fast, with stable URLs |

## 4. Definitions

- **Program**: a full training track (`/program/...`). **Course**: a single module (`/courses/...`). **Article**: guide or career content (`/articles/...`). **Lecturer**: `/lecturers/...`.
- **Domain**: the topic group used for headings (Embedded/Real-Time/FPGA, AI/ML/Data, Cyber, DevOps/Cloud, Web/Programming, QA, Other).
- **Featured**: an article listed in the curated `llms.txt`. All published articles appear in `llms-full.txt`.

## 5. Functional requirements

### 5.1 Serving

- **FR-1** The plugin serves `GET /llms.txt` and `GET /llms-full.txt` with status 200, `Content-Type: text/plain; charset=utf-8`, and no HTML wrapper.
- **FR-2** Responses carry `ETag` and `Last-Modified` and honour `If-None-Match` / `If-Modified-Since` with 304.
- **FR-3** `Cache-Control: public, max-age=3600` (configurable). `X-Robots-Tag` is not set to noindex.
- **FR-4** HEAD requests work. Other methods return 405.
- **FR-5** The URLs are served by WordPress rewrite handling only when no physical file with that name exists in the web root. Section 9 covers the server side.
- **FR-6** The plugin never renders either file through the theme or page-cache layer. It exits after output.

### 5.2 Content sources

- **FR-7** The plugin discovers all public post types, pages included, and the settings page shows them as a checklist. The editor ticks which to include, so utility pages (thank-you, templates, landing variants) stay out. Section headings and nesting follow the site hierarchy: the first URL path segment (`/program/`, `/courses/`, `/articles/`, `/lecturers/`) or the top-level parent page, with the post type label as the default heading. Child pages are listed under their parent.
- **FR-8** Only posts with status `publish` are included. Excluded: password-protected posts, posts whose rendered `<meta name="robots">` contains `noindex`, posts the editor flagged "Exclude from llms", and posts whose rendered canonical URL differs from their permalink.
- **FR-9** Each entry is `- [Title](URL): description`. URLs are the permalink with each Hebrew path segment correctly percent-encoded. Titles are the page H1 or post title with a leading "קורס " removed for course and program entries, as in the current files.
- **FR-10** The description is the content of the page's rendered `<meta name="description">` tag, read from the page HTML by a loopback request (not from any SEO plugin's stored fields). The same fetch reads the robots and canonical tags (FR-8). Results are stored in post meta with the post's modified time and fetched again only for new or changed posts. If the fetch fails or returns no description, the plugin falls back to the excerpt, then the first sentence of the content, and flags the entry in the Status tab. The text is stripped of HTML and shortcodes, whitespace-collapsed, and truncated at a word boundary to a configurable length (defaults: 170 characters for programs, 120 for courses and curated articles, 300 in `llms-full.txt`).
- **FR-11** Markdown-significant characters in titles and descriptions (`[`, `]`, and line breaks) are neutralized so a title can never break a link.

### 5.3 Grouping

- **FR-12** Each program, course and article belongs to one domain. Domain is stored as a taxonomy (`llms_domain`, non-hierarchical, non-public) with fixed default terms, editable in the settings page. Order and labels of domains are configurable.
- **FR-13** Posts without a domain appear under "Other" (נושאים נוספים) and are listed on a settings-page "Needs a domain" panel.
- **FR-14** A one-time bulk tool pre-assigns domains to existing content using the keyword rules from the generator script, shows the proposed result in a table, and applies it only after the editor confirms. It never overwrites a domain that was set by hand.

### 5.4 Output structure

**`llms.txt`** (curated):
1. H1 title and blockquote summary (editable text).
2. Key facts list (repeater of label and value, e.g. address, phone, email, recognition).
3. A pointer line to `llms-full.txt` (automatic, using the site URL).
4. Key pages (repeater of pinned links).
5. Programs by domain.
6. Courses by domain.
7. Featured articles by domain, capped per domain (default 7).
8. Lecturers.
9. Information and documents (repeater of links, e.g. voucher eligibility, recognition PDF).
10. `## Optional` with `llms-full.txt`, sitemap URL, privacy and accessibility pages.

**`llms-full.txt`**: same header, key facts and pointer back to `llms.txt`, then all programs, courses, articles (grouped by domain) and lecturers with longer descriptions.

- **FR-15** Within a domain, entries are sorted alphabetically by displayed title (locale-aware for Hebrew and Latin mixed text).
- **FR-16** Featured selection: an article appears in `llms.txt` when its "Featured in llms.txt" box is ticked. If no article is ticked in a domain, the plugin falls back to the most recently modified published articles up to the cap. The editor can switch the fallback off.
- **FR-17** Output is deterministic: the same content and settings always produce byte-identical files (so ETags are stable).

### 5.5 Admin

- **FR-18** Settings page under Settings -> LLMs.txt, restricted to `manage_options`. Tabs: General (intro, facts, pinned and optional links, caps, description lengths), Domains (labels and order), Content (needs-domain panel, bulk tool), Status.
- **FR-19** Status tab shows: live URL of each file with a "View" link, last rebuild time, entry counts per section, byte size, the detected conflicts (FR-27), and a "Regenerate now" button.
- **FR-20** A preview shows the generated text for either file before saving settings.
- **FR-21** The post edit screen gets one small meta box: "Exclude from llms files" and "Featured in llms.txt" (articles only), plus the domain selector. No other UI is added to post screens.
- **FR-22** All settings are validated, sanitized and nonce-protected. URLs in repeaters must be `http` or `https`.

### 5.6 Caching and invalidation

- **FR-23** Each file is built once and stored (object cache if present, otherwise a transient / option) with a content hash. A request never queries posts unless the cache is empty. Rebuilds happen from the nightly job (FR-24), the immediate removals and manual actions (FR-24a).
- **FR-24** A nightly job runs at 23:00 (default) in the site timezone. It finds posts that are new, changed, unpublished or deleted since the last run, fetches the meta tags for new and changed posts (FR-10), assigns a suggested domain to new ones, and rebuilds both files completely from the data. It does not append text to the old file, because entries are grouped and sorted. It writes the diff (added, removed, changed) to a log shown in the Status tab. The job uses standard WordPress scheduling (`wp_schedule_event`), with the run hour (default 23:00) interpreted in the site timezone from Settings -> General (`wp_timezone()`), so no server access is needed. Because WP-Cron fires only when the site gets a request, the plugin also runs a catch-up: if the last successful run is older than 24 hours, the next request or admin page load triggers it. A real server cron calling `wp-cron.php` is an optional improvement that the wizard suggests when it detects low traffic or a disabled WP-Cron.
- **FR-24a** Unpublishing, trashing or deleting a post, or flagging it "exclude", removes it from both files immediately, so the files never link to a page that returns 404 until the next night. Additions and edits wait for the nightly job. Settings save and "Regenerate now" also trigger an immediate rebuild.
- **FR-25** The rebuild runs under a lock so concurrent requests do not each rebuild. Others serve the previous cached copy.

### 5.7 Conflict detection

- **FR-27** The Status tab warns if: a physical `llms.txt` / `llms-full.txt` exists in the web root (the server would serve it instead of the plugin); any SEO plugin (Rank Math, Yoast or other) already serves `/llms.txt`; the live response of the URL is not produced by this plugin (checked with a header `X-RT-LLMS: <version>` that the plugin adds).

### 5.8 Setup wizard

The plugin must work on any WordPress site, not only these two, so first activation (and a "Run wizard again" button) starts a wizard that scans the site, shows what it found, and asks the installer questions only where the scan can't decide.

- **FR-28** Scan, read-only, with a results screen using plain language and pass / warning / blocker status:
  - Environment: WordPress and PHP versions, permalink structure, site timezone, memory limit, object cache, multisite, language and RTL, multilingual plugin.
  - Content: all public post types with counts, hierarchy (parent pages and URL prefixes), existing taxonomies and categories, ACF fields that look like a topic, sample of pages without a meta description.
  - SEO plugin: which is active (Rank Math, Yoast, other, none) and whether it generates an LLMs.txt or serves `/llms.txt` (FR-31).
  - Files and URLs: physical `llms.txt` / `llms-full.txt` in the web root, what `/llms.txt` and `/robots.txt` return now, the sitemap URL.
  - Delivery: loopback request test to a sample page, WP-Cron status (disabled or not, last run), whether a CDN such as Cloudflare is in front (response headers).
- **FR-29** Q&A, one short question per screen, each with a recommended default and an explanation:
  1. Which post types should be listed? (pre-ticked from the scan)
  2. How should pages be grouped: by site hierarchy only, by an existing taxonomy found by the scan, or by the plugin's own topic taxonomy?
  3. Site name, one-sentence summary and key facts (address, phone, email, recognition), pre-filled from the site title, tagline, schema data, or the contact page when found.
  4. Which language is the content in, and what should the intro say about it?
  5. Nightly run hour (default 23:00 site time).
  6. Which pages must be pinned as key pages? (suggested: home, about, contact)
  7. Should the plugin turn off the conflicting LLMs.txt feature (FR-31)?
- **FR-30** The wizard ends with a dry-run preview of both files, the list of warnings still open, and a "Go live" button. Nothing is served until the installer confirms. Answers are stored as ordinary settings and can be changed later in the settings page.
- **FR-31** Conflicts are resolved with the installer's consent, never silently. If Rank Math's LLMs.txt option is on (both sites), the wizard shows where to disable it and, once the installer agrees, turns it off using the SEO plugin's own settings API when the option is found at runtime; otherwise it gives step-by-step instructions and re-checks. If a physical file is present, the wizard cannot delete it from the web root without file permissions: it shows the path and instructions, and the plugin stays off until the URL is verified as served by the plugin (the `X-RT-LLMS` header).
- **FR-32** The wizard degrades gracefully: if a scan step fails (for example, the loopback is blocked), it reports that step as "unknown", explains the consequence, and lets the installer continue with a fallback (FR-10 fallback) or fix the cause first.
- **FR-33** Facts. The plugin supports structured facts at two levels, and prints only the ones that have a value:
  - Site-wide facts (settings page): address, phone, email, recognition and approvals, voucher eligibility wording, graduate and placement numbers, learning formats offered.
  - Per program and course (meta box, all optional): duration, learning format, price, prerequisites, certification, start dates. They are appended to the entry as a short factual suffix, for example `(60 hours, frontal, NIS 9,500)`.
  - Sources, in this order: a value entered in the plugin, then a value found in the page's own Course/Offer JSON-LD or an existing custom field detected by the wizard scan (shown for confirmation, never imported silently).
  - Numbers with a time sensitivity (placement rate, graduates) carry a "last updated" date set by the editor and are omitted from the files if older than a configurable number of months (default 12).

## 6. Non-functional requirements

| ID | Requirement |
|---|---|
| NFR-1 | Cached response time added by the plugin under 20 ms of PHP. A cold rebuild of about 520 entries completes in under 3 s and under 64 MB. |
| NFR-2 | Zero front-end assets, no external HTTP calls on page views, no cron job that runs more often than hourly. |
| NFR-3 | The plugin writes no files; it uses WordPress storage only. |
| NFR-4 | PHP 7.4+ and WordPress 6.0+; the wizard blocks activation with a clear message on older versions. Follows WordPress coding standards. |
| NFR-5 | Output is valid UTF-8 and renders Hebrew with technical Latin terms correctly. |
| NFR-6 | No private or draft content can appear. Tests assert this explicitly. |
| NFR-7 | Disabling the plugin removes the rewrite rules and returns the site to a clean state. Uninstall removes options, transients and the taxonomy terms (keeping the term assignments is a setting, default keep). |
| NFR-8 | Admin UI strings are Hebrew-ready (text domain, RTL safe). Default admin language English. |

## 7. Data model

- Option `rt_llms_settings` (array): intro, summary, facts[], pinned[], info_links[], optional_links[], caps, lengths, post types, switches.
- Taxonomy `llms_domain` (non-public) with default terms: embedded, ai, cyber, devops, web, qa, other.
- Post meta `_rt_llms_exclude` (bool), `_rt_llms_featured` (bool).
- Cache keys `rt_llms_cache_{short|full}` holding text, hash and build time.

## 8. External interfaces

- Reads the site's own rendered pages (meta description, robots, canonical) through loopback HTTP requests. No dependency on Rank Math or any other SEO plugin. The loopback must be allowed through Cloudflare and any firewall (see risks).
- 
- No other third-party services.

## 9. Deployment and server notes

- rt-ed.co.il runs Nginx behind Cloudflare. Nginx serves a file if one exists, so the old static `llms.txt` must be deleted or renamed first. This needs file access to the server, which the SEO pipeline does not have.
- Cloudflare may cache `.txt` URLs. Check cache status after deploy and set a cache rule or purge the two URLs by hand (the plugin does not purge the CDN, D4). The earlier stale-sitemap incident on this zone was a Cloudflare cache issue.
- Build and upload follows the existing plugin practice: zip built with PowerShell `System.IO.Compression` using forward-slash entry paths, repo on GitHub, installed through wp-admin. Roll out on the rt-ed.tech pilot first (9.1), then rt-ed.co.il staging.
- Rollback: deactivate the plugin and restore the static files from `llms/` (kept in this workspace).

### 9.1 Pilot on rt-ed.tech

rt-ed.tech is the pilot site before rt-ed.co.il. It already runs the custom RT Source Tracker plugin and is deployed manually, so the same zip and wp-admin install routine applies.

- The pilot proves serving, headers, caching, invalidation, conflict detection, the settings page and the load impact. It does not prove content equivalence with rt-ed.co.il, because rt-ed.tech may have different post types, content and an unrelated domain structure. The post type list and facts are therefore settings, not hard-coded values (FR-7, section 5.2).
- Pilot site settings use rt-ed.tech's own URL, intro and facts. Nothing from rt-ed.co.il's `llms.txt` is copied over unless the owner confirms the sites share content.
- Run the pilot for at least 1-2 weeks and check: server load before and after (the tracker plugin was the reason for the slowdown history), the rebuild count in the Status tab, crawler fetches in the access log, and that new or unpublished content shows up correctly.
- Promotion rule for rt-ed.co.il: acceptance criteria 1-8 pass on rt-ed.tech, no load regression, no unresolved review findings. Criterion 9 is checked on rt-ed.co.il after install, preferably on its staging copy first.
- Both sites run the same plugin build. Pilot findings go back into the repo before the production zip is built.

## 10. Acceptance criteria

0. On a site with a different structure (test on a clean WordPress with default post types and no SEO plugin), the wizard completes, produces a valid preview, and serves the files after "Go live" with no manual code edits.
1. Publishing a new course makes it appear in both files after the next rebuild, and unpublishing or deleting it removes it, without a manual step.
2. `curl -I https://rt-ed.co.il/llms.txt` returns 200, `text/plain; charset=utf-8`, the `X-RT-LLMS` header, and 304 for a repeat conditional request.
3. A draft, a noindex post, a password-protected post and a post flagged "exclude" never appear in either file.
4. Every URL in the files returns 200 (checked by the same link test used on 2026-11-02, 515 links).
5. A course named with `[` or `]` does not break the surrounding link in the output.
6. After installing on staging, the Status tab lists no conflicts.
7. Under a 50-request burst on a cold cache, only one rebuild runs.
8. With the plugin deactivated, the site has no plugin rewrite rules left and no errors in the debug log.
9. The generated `llms.txt` is functionally equal to the reviewed 2026-11-02 file (same sections and entries), apart from intentional differences.

## 11. Test plan

- Unit tests for description fallback and truncation, Markdown escaping, Hebrew URL encoding, domain assignment, featured fallback, determinism (hash stable on rebuild).
- Integration tests for invalidation hooks and exclusion rules, run in the WordPress test suite.
- Manual on staging: conflict detection with the old static file present, Cloudflare caching behaviour, Hebrew rendering in a browser and with `curl`.
- Code review in repeated rounds before shipping, applied on the owner's explicit go-ahead (project practice).

## 12. Decisions, assumptions and install-time checks

### 12.1 Detected by the plugin at install (not decided in advance)

Nothing about a specific site is hard-coded. The wizard (5.8) detects each of these on the site where it is installed and either configures itself or asks the installer.

| Item | How the plugin finds out | If it can't |
|---|---|---|
| Post types and hierarchy (FR-7) | Scans all public post types, counts and URL structure | Installer ticks types manually |
| Topic grouping (FR-12) | Scans taxonomies, categories and ACF fields for a topic-like field | Creates its own taxonomy |
| Competing LLMs.txt: Rank Math option, other SEO plugin, physical file in the web root (FR-27, FR-31) | Checks active plugins and their settings, the file system, and the live `/llms.txt` response and headers | Shows instructions and keeps the plugin off until the URL is verified |
| CDN / cache in front (Cloudflare) | Response headers (`cf-ray`, `cf-cache-status`) | Asks the installer, shows what to configure in the CDN |
| Timezone, WP-Cron health, PHP and WordPress versions | WordPress APIs | Warns and continues with defaults |
| Loopback to read meta tags (FR-10) | Test request to a sample page | Uses the excerpt fallback and flags it |
| Facts and intro | Site title, tagline, schema data, contact page | Asks the installer |

Known today from outside, for planning only (the plugin does not rely on it): rt-ed.co.il is behind Cloudflare and serves a `/llms.txt` last modified 2025-07-08; rt-ed.tech runs Nginx 1.18 on Ubuntu with no Cloudflare and returns 404 for `/llms.txt`. Both run Rank Math with its LLMs.txt option on, which must be disabled (FR-31).

### 12.2 Decisions made

| # | Decision |
|---|---|
| D4 | No Cloudflare API purge. The plugin relies on a short cache lifetime (FR-3) and never stores CDN credentials. If a CDN is detected, the wizard and Status tab tell the installer what to configure (a cache rule or a manual purge), because the CDN is outside the plugin's control. FR-26 is removed. |
| D5 | The files should carry every fact the site can provide: duration, learning format, price, prerequisites, certification or recognition, voucher eligibility, graduate and placement numbers. The plugin never invents or guesses a fact; it publishes only what exists. See FR-33. |
| D7 | The plugin lives in a new branch of the existing repo https://github.com/ofirseort-lang/wptracker, in its own folder `rt-llms-txt/` beside `rt-source-tracker/`, so the two plugins never share files. The branch is named `feature/rt-llms-txt`. |

## 14. Risks

| Risk | Mitigation |
|---|---|
| A plugin bug serves an error to crawlers | Serve the last good cached copy on any build error; staging first; quick rollback to the static file |
| The plugin adds server load | Cached responses, deferred single rebuild, no front-end code (NFR-1, NFR-2) |
| Domain data is wrong or missing | Needs-domain panel, "Other" fallback, bulk tool with confirmation |
| Cloudflare keeps an old copy | Short TTL (D4), CDN instructions in the wizard, check after deploy |
| Another plugin overrides `/llms.txt` | Conflict detection and the `X-RT-LLMS` header check |
| Loopback fetch is blocked (Cloudflare, firewall, auth) so meta tags can't be read | Fallback to excerpt with a flag in the Status tab; allow-list the server's own IP; test on the pilot |
| Nightly job misses its slot (WP-Cron needs traffic) | Real server cron, a "last run" warning in the Status tab, manual "Regenerate now" |
